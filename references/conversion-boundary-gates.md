# Conversion Boundary Gates

在转换开始前和交付前分别执行门禁。门禁只约束会改变页面结构、原生所有权、视觉结果或工程安全的事项，不把接口和动态业务实现升级为转换核心。

## 转换前门禁

必须确认：

- 输入可运行且渲染稳定；时间、随机数、异步内容、轮播和动画有确定性采样状态。
- 已确定页面范围、移动端根容器、目标 viewport、方向、外观、语言和基准状态。
- 来源已分类为移动画板、移动响应式页面、桌面专用页面或歧义来源。
- 新项目已由用户选择 SwiftUI/UIKit；已有项目已确定目标 project、target、source root 和目标模块技术栈。
- 已明确状态栏、NavigationBar、TabBar、Safe Area、滚动容器、固定栏和弹层的原生所有权。
- 关键字体、图片、SVG 和背景资源可访问，或已有保持尺寸与裁剪语义的占位方案。
- 路由、presentation 和会改变 required state 的交互没有未决目标。
- 生成目录、命名前缀、已有类型冲突和人工修改文件的 ownership 已检查。
- 最低 iOS 版本与候选 API availability 已核验。
- 已有项目的验证模式已确定；未经用户同意不构建或启动大型 App。

以下情况必须返回 `needs-input` 或 `failed`，不得生成正式代码：

- 新项目未选择 SwiftUI/UIKit。
- 多工程、多 target、混合技术栈或页面根无法唯一判断。
- 来源是 `desktop-only`，但用户没有指定移动范围或允许移动适配。
- 关键系统区域或路由/presentation 所有权存在会改变 UI 架构的歧义。
- required state 无法稳定复现，或主要视觉内容由不可访问资源构成。
- UI IR 无效、关键控件映射置信度低于门槛且未复核、交互仍为 `requiresResolution`。
- 目标生成文件与人工文件或已有类型发生无法安全合并的冲突。

以下项目可带警告继续，但必须写入降级清单：

- 非关键装饰资源缺失。
- 动画无法确定性截取全部中间帧，但静态端点和交互结果可验证。
- 原型未定义接口、业务数据源、权限流程或错误恢复逻辑。
- 文件、相机、相册、定位、分享等系统入口只有视觉定义，没有 entitlement、隐私文案或业务生命周期。
- `month`、`week`、多选文件等没有直接等价系统控件的值域；允许先还原入口视觉，但必须标记为自定义 picker 或待业务接入，不能伪装成完整系统能力。

## 转换中约束

- 先由可观察语义、状态和行为选择原生控件，再还原视觉；不得只按 HTML tag 或 class 名映射。
- 优先复用目标模块的现有组件；系统控件无法覆盖视觉时使用组合 View、自定义 UIControl/View，只有独立生命周期才自定义 ViewController。
- 不得使用 `WKWebView`、整页截图或功能区域截图代替原生结构。
- 页面根滚动轴、嵌套滚动轴和 fixed/sticky 区域分别建模；横向溢出不能自动把纵向页面升级为双轴滚动。
- 原生容器使用完整父级 bounds；Safe Area 由唯一 owner 管理，不从容器宽高预减。
- 保留源码视觉顺序、Flex reverse、Grid order、文本 Range 顺序、图标槽位和紧凑控件宽高比。
- 使用 Auto Layout/SwiftUI layout 表达响应式关系；固定来源尺寸只作为约束证据，不生成整页绝对坐标或运行时整体缩放。
- 只生成当前可见视觉 fixture 和必要局部状态，不猜测接口、分页器、业务 ViewModel、认证或支付逻辑。
- 文件名、目录、入口和路由遵循项目架构及 generated ownership；不覆盖人工源码和现有启动流程。
- 每个降级项必须标为 `native`、`native-fallback`、`project-component`、`placeholder` 或 `unsupported`。

## 转换后门禁

正式交付前必须确认：

- 生成源码、Payload、资源和 target membership 完整，入口状态准确。
- 生成源码通过 Swift 类型检查；选择 `build` 或 `visual` 时目标 scheme 构建成功。
- 选择 `visual` 时，required HTML/iOS 状态齐全、截图尺寸一致且确定性像素门禁通过；`build` 模式不要求生成截图。
- 选择 `visual` 时，首屏、长页末端、弹层、选择/禁用/焦点等 required state 已验收。
- 页面根没有非预期横向移动；嵌套横向列表没有纵向漂移。
- NavigationBar、TabBar、状态栏、Home Indicator、Safe Area 和固定操作栏没有重复占位。
- 文本顺序、单行/多行、截断、baseline、图标前后关系、紧凑 item 尺寸和正方形资源槽位已校准。
- 320/375/393/430pt 中适用宽度没有文字遮挡、约束冲突或文档级横向溢出。
- 资源缺失、视觉降级、未覆盖系统生命周期和未运行验证均已明确记录。

不得声称“核心转换及编译完成”的情况：

- 构建失败，或没有按已选择的验证模式执行。
- 页面根滚动轴错误、系统栏重复、关键资源缺失或主要控件映射仍未解析。
- 为通过单张截图而破坏原生架构、响应式约束、控件语义或其他 required state。

不得声称“视觉验收通过”的情况：

- 没有选择并执行 `visual`。
- 任一 required state 缺失或超过视觉阈值。
- 多模态 review 未运行可以如实标记为 `not-run`，但不能伪称已完成人工看图走查；确定性门禁仍可独立通过。

多模态走查只能补充像素门禁，不能替代构建、状态断言和确定性差异检查。
